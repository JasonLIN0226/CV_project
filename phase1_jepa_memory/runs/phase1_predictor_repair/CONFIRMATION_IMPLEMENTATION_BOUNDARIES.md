- A staged implementation must preserve the original simulator, opaque IDs, per-split stable seeds, original sample tensors, actions, targets, and fitting definitions. Never feed simulator metadata or labels into the predictor. Final evaluation must bind both training and test provenance and independently verify every requested pair and seed.

## Feasible staged data/cache boundary

Use one canonical fresh config with both tasks and the full final pair counts. Track candidate/reference roles and the confirmation stage in the new protocol/signatures, rather than setting the legacy `experiment.arm=confirm_candidate`. A canonical config without that legacy routing field preserves original `[start,end]` Motion selection and ranking weight 0.5. The new explicit trainer still enforces candidate Gate anchor 1/Motion 0 and original reference training settings.

Share a single canonical dataset/encoder cache across both tasks and both model roles. The 198656 frame bound counts that cache once; naively encoding a separate two-task dataset for each role/task would double or quadruple the cost. Original normalization fits all training records across both tasks; keep that definition. Basis/readout fits remain task-specific and train-only.

The original `dataset_signature(c)` depends on the canonical data config and original core renderer/data source, not the number of currently materialized records. The original feature-cache signature depends on that canonical dataset signature, encoder config and encoder/cache implementation. A separately source-locked staged writer can therefore create only train/validation records first, retain the canonical logical signature, and append the fixed tests only after the all-12-model lock. This must be disclosed as an incomplete training-only stage, never falsely marked as a complete original audit.

Implement a strict training-only `FeatureStore` constructor that requires complete train/validation stage pairing, source/checksum/shape/finite/feature equality proofs and exact allowed IDs. Inherit the original sampling/project/normalize behavior where possible, with actual tensor/RNG equivalence on development data. The original `load_feature(c, rec, ix)` accepts an explicit index and can validate each actual feature without calling the full-cache loader. Do not bypass `require_audit` globally or weaken the original complete loader. Keep an immutable digest of the actual training subset and every fitting input.

For initial normalization, reproduce the original float64 sum/squared-sum loop, ordering and floor on training records only; bind its metadata to the canonical cache signature and all 2048 fresh train episode IDs. `fit_basis` can then use the strict staged store with the unchanged original PCA and train-only code. Since train IDs, numerical normalization/basis files and canonical cache signature stay unchanged when tests are later appended, current model proofs can bind them across stages. Final audit must explicitly compare all frozen training records/features/transforms and full final pairing/counts, not silently accept an index-file hash change.

After all 12 models are complete and locked, generate/encode all three tests, run the original full data and feature-pair audits, and construct a complete final store. Evaluate freshly trained reference and candidate weights on identical axes. With validation plus all three tests, expected raw rows are 62208 per task, 124416 combined; preserve all six evaluation conditions, both horizons and all seeds. Adapt independent audit count/path/provenance guards explicitly for the fixed fresh counts while preserving its metric and acceptance arithmetic.
