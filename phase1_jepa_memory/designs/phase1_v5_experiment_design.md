# Phase 1 历史证据与不可逆删除实验新设计

本方案把真实流式视频作为主要实验环境，保留既有 Gate 和 Motion 作为严格的机制压力测试。核心问题是：历史证据能否被预测器使用，不同删除选择是否产生可测的未来损失，以及这种差异能否在连续删除中保持。第一阶段先建立可信的预测器和评估协议，再进入学习删除策略的阶段。

状态：完整设计提案，尚未实现或运行。旧实验的 REJECTED 和 NOT_ELIGIBLE 结论保留。真实视频上的辅助可行性结论不能替代原任务的验收标准。

**一 为什么重构以及哪些内容值得借鉴**

当前实验回答了一个必要问题：在配对近期观测相同的情况下，历史是否改善预测。它还没有完整回答原 idea 中的连续 B+1 到 B 删除问题。可读的输入特征、足够的输出空间、成功的未来预测和可学习的删除策略，是不同的证据层级。

|来源|采用的实验原则|在本方案中的落实|
|---|---|---|
|[SPACE](https://arxiv.org/html/2609.32592v1)|真实视频流、共同冻结预测器、相同容量下比较删除；同时衡量任务效果、稳定和适应|Assembly101 单机位；共同预测器；连续删除回放；动作切换与扰动恢复分开报告|
|[EMR 补充材料](https://aclanthology.org/attachments/P19-1434.Supplementary.pdf)|先检查任务模型能使用关键证据，并把证据保留与实际任务表现分开|先验证编码器读出及历史预测收益；合成任务报告证据可用性与预测误差；真实视频不虚构唯一支持事实|
|[RNP](https://merl.com/publications/docs/TR2026-095.pdf)|同一预测器和实际未来下比较所选记忆与反事实记忆|冻结预测器，成对测量删除的即时与延迟后果；不引入它的 PPO 和共同适应|

第一阶段不加入 SPACE 的慢空间、吸引子控制器或检索效用库，也不加入 KVP 的未来注意力代理、NGC 的联合强化学习。这些会增加尚未定位的因素。保留冻结编码器、train-only 拟合、三个种子、共同选模、真实目标以及独立确认。

**二 数据从单次提示改为真实流式上下文**

主数据采用 Assembly101。它包含自由顺序的装配和拆卸，以及错误和纠正，适合观察长期上下文与任务变化；这些标注反映活动变化，不等于完整的物理状态真值。[官方数据集](https://assembly-101.github.io/)

只使用 C10095_rgb 固定机位，避免先引入多视角融合。采用 SPACE 公共脚本中的 29 人训练、10 人验证、9 人测试划分；这是该论文自定义的按参与者划分，不是 Assembly101 原始任务划分。所有来自同一个人的录像只能进入一个集合。[划分来源](https://raw.githubusercontent.com/GilliaN-HJ/SPACE/main/scripts/prepare_assembly101_tsm.py)

课程规模的首轮每人预选两条录像，按固定字符串 v5-manifest-27183 与录像名的 SHA256 排序取前两条，不读取动作内容或结果选择录像。官方公开目录已给出可构成训练 58 条、验证 20 条、封存测试 18 条的名单。该数量是目录规划结果，不代表文件可下载、时长合格或特征可用。清单见同目录 phase1_v5_assembly_metadata_selection.json。

每条录像按视频时间采样 2 FPS；取开头最多四个完整的 256 帧非重叠片段，每段 128 秒。片段不足 256 帧不补零、不拼接其他录像，记录原因；参与者没有合格片段时停止并报告，不按模型表现补换录像。这个阶段研究有限长度流上的删除可行性，不声称验证无限时长部署。

每段只在开头重置记忆。真实分支的有效预测查询从 t=40 开始，保证 recent 加最大次要容量32已经填充，并且四个未来目标都在片段内；固定每四个采样步评价一次。所有策略及容量使用相同查询，不能各自选择有利时间。先按参与者划分，再切片，禁止随机把相邻帧分入训练和测试。

时间对齐使用视频实际 PTS 和明确的标注时基。官方说明原视频为 60 FPS，标注帧编号基于 30 FPS 抽帧，不能直接用原视频帧编号连接标注。[标注说明](https://raw.githubusercontent.com/assembly-101/assembly101-annotations/main/README.md)

|设置|真实视频分支|原合成压力分支|
|---|---|---|
|近期缓冲|8 帧，约 4 秒|4 帧，保持原定义|
|主要历史容量|16 条|2 条|
|容量敏感性|8、32 条，只作固定的次要检查|不改容量|
|预测未来|1、4、16、64 步，即 0.5、2、8、32 秒|h3、h6 不变|
|目标|完整冻结视觉特征，及独立读出的未来动词|原完整特征、位置与任务指标|
|数据用途|58 条训练、20 条开发验证、18 条封存测试|6301 仅开发；9137 保留独立确认|

既有物理生成器、长延迟 20–32、训练延迟 5–10、原联合干扰 OOD 和配对近期观测条件不改。新的主数据增加外部效度，旧数据继续检验视觉历史、动作及未来之间的严格关系。

**三 编码器保留 时间边界明确**

采用已核验的官方冻结 I-JEPA，同一 revision、官方无裁剪 processor、grid2、float32 和编码 batch 2。真实视频每个特征只来自该时刻的一张 RGB；禁止使用以该时间为中心、实际包含未来帧的特征。特征、归一化和基底缓存均保存来源哈希。

SPACE 采用官方 TSM 预提取特征；官方特征说明是八帧输入，因此在不了解窗口与特征时间戳的关系时，不把它直接当成我们的严格因果输入。这是需要核实的支持范围，不是对其特征泄漏的断言。[官方特征说明](https://github.com/assembly-101/assembly101-temporal-action-segmentation)

真实视频的均值、尺度、128 维输入投影和128维输出残差基底仅用真实视频训练参与者拟合一次。原合成开发继续使用其已有 train-only 拟合，避免把改变归一化或基底混进读出器对照。输出误差始终在完整归一化特征空间计算，不能只在容易预测的投影内计算。

**四 预测器更新为可处理任意保留集合的时序模型**

默认候选为一个小型因果 Transformer：hidden 256、2 层、4 个头、FFN 1024。使用已投影的视觉内容、真实时间与近期或历史标记；预测查询只读取合法观察。删除后每个保留条目的真实时间不变，不能重新编号后让位置编码产生额外变化。

它替换原来的手工速度回归、动作对齐及线性运输读出。原因是这些模块限定了匀速物理假设，不能直接推广到装配活动；这项更新也检验旧读出器的限制是否影响证据利用，不假定它已经是失败原因。

每个数据任务和种子拥有一个预测器，全部记忆策略共用该模型。真实视频不输入未来动作标签；合成任务只提供原来合法的已知过去控制和逐 horizon 的计划控制前缀，h3 不能通过共享表示读取 h4 到 h6 的控制。

真实视频预测器训练 30 轮，AdamW、学习率 0.0003、weight decay 0.05、batch 64、warmup 5%、模型 dropout 0.1，历史 dropout 0.15。均衡训练 recent-only、FIFO16、Reservoir16、片段完整历史四种条件，记录 dropout 后实际条件覆盖。四个 horizon 的完整特征 MSE 等权，选择最早的等权 validation MSE 最小值。没有动作标签辅助损失或策略专用预测器。

原合成桥接对照只更换读出器。候选仍使用原 120 轮、batch64、优化器与调度、均衡四条件、MSE 加 2 倍配对差分 MSE 加 0.5 倍 ranking、模型 dropout0 和原选模规则。对照使用真实完成的 v3 reference，而不使用未匹配的历史 v2 best。参数量、训练步数、耗时与 forward 成本分别报告，不宣称架构计算成本相同。

训练种子均为17、29、43。新增开发训练为真实视频三个预测器、Gate 三个候选、Motion 三个候选，共九个；已有六个 v3 reference 仅作为固定开发锚点。各分支完成全部三个种子并核验模型后才评价开发测试。

**五 第一阶段按依赖分成三个实验**

**A 证据是否可用**

先在训练真实特征上拟合一个固定的24动词线性 sigmoid 读出器，仅用 train 标签，固定 L2 为0.001、200轮、Adam学习率0.001、batch256、seed0；验证集只检查，不调参。每个时刻的标签由同时有效的细粒度动作取动词并集；动作 NLL 定义为24个 Bernoulli 负对数似然的均值。主任务分数包含全部合法查询，前景、背景和动作变化结果另外分层，不能按是否有利删除查询。它首先对真实未来特征进行读出，与训练标签频率构成的常数预测比较，同时报告 macro mAP 和 Recall@5。标签不进入预测器或记忆策略。

再让同一读出器评价预测出来的未来特征，比较 recent-only、完整片段历史、FIFO 和 Reservoir。同时检查输出基底的 true-future 投影重构上界，区分输入表征、输出空间和预测器三个可能的限制。上界使用真实未来，只是不可部署诊断。

开发可行性要求：真实未来读出优于常数先验；完整历史在 h16、h64 的视觉 MSE 和未来动词 NLL 对 recent-only 有正的配对区间，每个种子及按参与者汇总均成立。短 horizon 和动作切换切片必须完整报告，不能只展示有利的长 horizon。这是新增的信号检查，不是原10%门槛的替代。

合成任务同时使用原证据 probe、任务读出及 wrong-evidence 干预，并保留全部原 GO 要求。若输入可读但未来预测仍失败，不能把失败归给删除策略。

**B 删除后果是否可测**

冻结所有预测器、基底和读出器。在真实视频 FIFO 与 Reservoir 的满记忆状态，加入刚退出近期缓冲的条目，形成17个候选，逐个删除，全部结果维持16条历史。候选保留相同近期观测、时间信息与实际世界未来。

每条训练或验证录像、每种来源策略，按固定种子从所有合格片段的有效满容量时间中均匀取四个状态，不依据损失挑选。先逐状态记录全部17种删除的四个未来误差，再进行32步共同 Reservoir 延续。延续使用相同观察和共同随机数；所有候选共享原预测器。

删除代价固定为即时四-horizon平均 MSE 与32步延续平均 MSE 各占一半。后者每步重新生成合法近期上下文，所有目标需要位于片段内。一个状态只按这个共同目标选择一次 oracle 删除，代价平局取较早真实时间条目；h16、h64 分别报告这个同一选择的结果，不按各 horizon 另挑最佳选择。选择删除最小代价条目需要未来，因此只能构成 oracle 对照。

输出逐候选损失、最好与最坏差异、相对 FIFO 和 Reservoir 的 oracle 余量、即时和延迟排序差异以及并列状态比例。原始17候选的动词 NLL 也完整报告，用来检查视觉代价排序是否与任务效果一致。验证信号要求共同目标及其 h16、h64 代价相对两种基线的区间均为正，每个种子分别成立；未支持时记为未解决，不能继续声称策略可学习。

合成任务采用同样的 B+1 到 B 检查，始终保持两条历史。Gate 比较删除提示与删除填充条目；Motion 分别比较删除 start、end 和填充条目，不把末帧保留当作方向信息保留。已存在的两帧速度读出、basis oracle 结果不能代替这项比较。

**C 作用能否在连续删除中保持**

整段顺序回放，近期8帧与长期16条始终不重叠。空槽直接插入；满时从旧16条加新1条中永久删除一条，包括拒绝新条目。删除内容不能在后续策略决策中从特征文件重新取回。每个保留条目的视觉内容和时间记为持久记录，不额外携带以前看过但已删除的视觉摘要。

必要的在线对照只有 FIFO、Reservoir 和均匀随机删除。recent-only 检验有没有历史收益，完整片段历史只作容量放宽参考。oracle 需要未来，仅作诊断；第一阶段不训练新删除策略。

同时报告每个 horizon 的视觉误差与动作 NLL、连续满容量更新数，以及动作未变时的预测变化、动作切换后的响应。加入一个预定的50%历史内容替换检查：使用同片段更早、标注活动不同的内容替换八条记忆，保留时间，干净与扰动分支接收同一后续流，比较0、1、2、4、8、16步恢复。只有评估器的故障注入可以访问这个历史供体，在线策略不获外部历史访问权；仅对主容量16执行该检查。没有合格时点或供体就记录缺失，不制造样本。

这些标签只用于分层与干预定义，不提示策略发生切换。稳定性必须与任务误差一起解释，恒定输出造成的小漂移不构成成功。真实视频不报告凭空定义的支持事实存活率；在合成数据上，证据时间命中、等价视觉证据和实际预测效果分开报告。

**六 统计与成功含义**

真实视频先在片段内汇总，再在录像内汇总，最后给每个参与者等权。参与者是 bootstrap 单位，固定10000次、seed0，报告双侧95%区间及三个种子的分别结果。连续帧、多个删除候选和同一录像的片段不是独立样本。合成任务继续按 base pair、2000次 bootstrap、原比例或低基线绝对收益规则处理。

真实开发返回 REAL_FEASIBILITY_SUPPORTED、REJECTED 或 INCONCLUSIVE，不返回 Phase 1 GO。它需要 A 的历史收益与 B 的 oracle 余量在 h16/h64 和三个种子均有正区间；回放和扰动的原始结果必须齐全。C 的不同简单策略可能并列，不要求人为保证某个启发式胜出。

原任务候选采用仍需所有原规则，包括逐种子 ID/OOD、原10%收益、wrong-evidence、任务读出、对固定 v3 reference recent 的收益，以及关键切片候选 privileged 绝对误差对 reference privileged 的可靠降低。真实视频进展不能挽救失败的合成种子。

只有两项合成开发采用对照都通过、真实开发信号支持、所有当前权重证明有效后，才开启独立确认。合成确认继续 seed9137、原每任务512/96/256/256/256 pair、原物理与阈值；重新训练 reference 与候选共12个模型并全部锁定后开测试。真实确认评价此前封存的九人18条录像，直接使用锁定的真实预测器和读出器，不在这九人上选模型或修复方法。确认失败后保留失败，不重复调整同一确认集。

阶段1完成只说明历史与删除实验底座可信；oracle 余量不证明线上策略可学会。之后的轻量、集合条件、仅过去信息的删除策略需要单独协议和新的未暴露评价，属于阶段2。

**八 结果包与当前决定**

交付包括冻结配置与清单、每种子的完整曲线及checkpoint证明、每个条件的原始标量预测记录、17候选删除表、不可逆回放轨迹、三个层级的判定和保留的所有失败。大视频、特征及权重留在课程HPC，仅原生取回小型报告、图表和标量记录，并核验checksum。

本方案建议以真实数据和直接删除实验替代继续围绕旧损失项试修。原Gate common-anchor尚未训练，保留为未检验假设，不自动并入新候选；pure-velocity已不满足原预注册，保持停止。当前只完成设计与公开目录清单，没有下载Assembly101内容、训练模型或生成新科学结果。
