# Equal-capacity deletion assay (prospectively fixed)

Purpose: assess whether the existing frozen predictor supplies usable deletion-cost supervision, as requested by the human. This is a new mechanism assay, not a retroactive pass of the previous predictor-adoption protocol and not a learned retention-policy result.

Reuse the latest *complete* second-repair models, job7574, for BOTH tasks and all seeds17/29/43. No choice among repairs based on deletion results. Reuse the original6301 cached test pairs:128 ID,128 long-gap,128 distractor-shift per task. No new training, fitting, encoding, fresh9137 access or model selection. All old failures remain.

Each fork starts with the same3 timestamped candidates, same4 recent frames, action continuation and future. Delete each candidate in turn; every model call retains exactly2 real historical entries. All entries enter the predictor. No zero padding masquerades as history; no hidden state, role, pair ID, sibling or target enters a model call. Reset each fork to its common parent; this is a one-decision assay, not an irreversible streaming evaluation.

Gate parent: original cue timestamp plus the2 latest post-cue historical frames; secondary parent uses the2 earliest post-cue frames. Motion parent: original two evidence timestamps plus latest shutter frame; secondary uses earliest shutter frame. Only timestamps already known from original controlled-task evidence metadata define these privileged diagnostic pools. They are NOT an online retention policy. The primary parent includes the actual newest historical arrival; secondary is a static sensitivity test. Require distinct legal times before the recent buffer. Gate's other visible cue frames and Motion's other pre-shutter positions are deliberately excluded: no undeclared redundant evidence remains in these3-entry parents. The last visible cue time is computed from the original manifest clock query-gap-recent; Gate nuisance must follow this entire1-3frame cue window, not just its first annotated timestamp.

For every deletion, record full5120-dimensional normalized feature MSE and frozen state-readout task error (Gate lane error, Motion position MSE), separately for h3/h6. Simulator truth is read only by evaluation after forward. Raw scalar rows and trace IDs stay on HPC. Candidate/source/cache/model/readout SHA ledgers must be stable before/after. Repeat a fixed first batch, permute same-time entry order, and change only the unavailable h>3 action suffix: compare actual outputs for determinism, set ordering and h3 causality. These software checks are necessary, not scientific effects.

Primary, narrowly scoped entry decision: ID deletion signal, both tasks, all3 seeds, both horizons, each critical role (Gate cue; Motion start and end). Within each base pair first average siblings and the two parent variants. Critical-deletion loss minus nuisance-deletion loss must have positive paired-bootstrap lower95%CI and >=10% relative aggregate reduction from retaining the critical evidence, for BOTH feature and task errors. For nearly zero critical-deletion error (<1e-8) the comparison is inconclusive, not an inflated ratio. Bootstrap10000 seed0; units are128 independent base pairs, never siblings, forks or seeds. The 10% material-effect floor is explicit and fixed before any deletion outcomes. All contrasts must pass (intersection decision; no cherry-picked seed or model).

Additionally require a transferable deletion ranking: select the lowest-feature-loss deletion using h3, score against uniform-random deletion at h6, then reverse horizons. Decisions are evaluation oracles, not past-only policies. Average ties within1e-8 instead of tie-breaking toward the evidence label. Each task/seed must have positive paired-bootstrap lower95%CI for feature AND task advantage in both directions. Report rank agreement and oracle headroom descriptively; same-horizon min-versus-random is optimistically selected and is never sufficient to pass.

Long-gap and distractor results apply the same frozen contrasts and are reported separately as scope limitations. They cannot be silently averaged away. ID support licenses only an ID-bounded retention-policy PILOT, not robust deployment, full original Phase1_GO, unseen-data confirmation or policy learnability. If either task fails ID contrasts/ranking, do not start joint policy training. Gate-only support may justify a clearly scoped Gate pilot. No automatic policy training is authorized by the assay's result.

Before execution also fix descriptive equal-capacity baselines: FIFO delete-oldest, reject-newest, uniform deletion and the future-feature oracle (average ties). These simple privileged pools may favor reject-newest, so a positive critical-versus-nuisance contrast does not establish headroom over strong retention baselines. Do not call uniform one-step deletion a complete streaming Reservoir evaluation. Baselines cannot change the primary readiness rule.
