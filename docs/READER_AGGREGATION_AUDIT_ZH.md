# Reader 聚合诊断：旧数据能说明什么

**状态快照：2026-10-25，CPU 探针和旧 checkpoint 的 uniform 干预已完成。** 本轮源码已冻结为 `82e31a0ecc555d9a9a7ffa6b13282dad00b9bef5`。作业 **11544 已在 NVIDIA A100-SXM4-40GB 上实际运行**，CUDA 已确认；作业已开始训练，五臂尚无完整结果。新诊断和原 CONF 均未打开。此为本文更新时的运行快照，不是五臂实验完成或新 reader 改善的结论。
完整 CPU 数据可从[本轮 Release](https://github.com/JasonLIN0226/CV_project/releases/tag/reader-aggregation-20261025)下载 `reader-aggregation-cpu-results.zip`（SHA256 `2732b5bb6c7bff0acc9d38cfc2501cf80477211e0a81d1f824ea6838c464f06e`）。包含逐条干预预测系数、重建 basis/current、36 个 probe 模型、TRAIN/VAL/旧 DEV 的冻结输入切片，以及全部指标与校验清单；可以直接交给其他审阅者分析。[仓库内的紧凑证据](../results/literature_diagnosis/reader-aggregation-20261025/)保留审计表与摘要。


前半部分用 [audit_reader_attention.py](../experiments/phase2/audit_reader_attention.py) 复核旧 run 保存的数据，不重新推理；后半部分报告新完成的 CPU 探针拟合及无训练权重干预，评价仍限于旧 DEV。旧 DEV 共 24 个独立 family、1728 个 parent；其中 S 为 1152 个，不能把所有 factorial 记录当作独立场景。本地复核输出为 `build/reader-aggregation-20261025/audit/reader_attention_audit.json`。整体实验、资格门槛与原始发布包见[旧报告](TERMINAL_THREE_STRUCTURES_REPORT_ZH.md)，本轮约束见[已冻结预注册](READER_AGGREGATION_PREREGISTRATION_20261025.md)。

**0.658 与 0.0086 是当前 reader 的读取偏向，不是重要性的标签。**

S 的 K3 候选中，tag=1 单条目的平均 attention 为 **0.658079**，tag=0 为 **0.008588**；两组各有 1728 个候选条目。这是当前 query 下三个候选的 softmax，不是 future-attention 监督，也不是每个 episode 两类 tag 的总权重。

当正确 pair 的 tag=0 时，它们在 K3 中的合计权重平均只有 **0.020663**；正确 pair 为 tag=1 时则为 **0.994899**。读取错误也明显不对称：实际 episode 计划下，256 个“K2 完整 pair 读对、加入第三项后 K3 读错”的样本，253 个的正确 pair 是 tag=0，只有 3 个是 tag=1。

这支持“当前 reader 的读取分配值得检查”，却没有单独证明 softmax 造成全部错误。加入第三项同时改变了 memory、时间均值、velocity、动作交互等输入；现有结果是集合内容干预，不是只改 attention 权重的因果实验。K2 与 K3 的资格仍应分开：S 的 K2 通过、K3 未通过，不能概括成整个 S reader 都不合格。

**K2 的两个权重并非总是各 0.5。**

旧 scorer 对每项独立计算 logit，删除第三项后，可以将保存的 K3 权重在剩余 pair 内重新归一化，准确得到 K2 权重，不需要新推理。1152 个完整 pair 中，只有 **288 个（25%）**在既定数值容差内均匀；单项权重范围为 **0.101341–0.898659**。相同 tag 不代表相同 payload 或外观，因而不保证相同 logit。把每对两个权重一起求平均当然总是 0.5，这只是它们和为 1 的恒等式。

**约 74% / 85% 是已知方向 bit 的正确率，不是完整未来预测正确率。**

这是旧 reader 的“单条 cue＋当前空白帧”固定时间检查。从最近未来原型的类别中，取出该 cue 对应的那一位；D 的无关诱饵不参与此统计。

| 显眼 cue 条件 | 已知方向 bit 正确 | 完整四类未来正确 |
|---|---:|---:|
| R | 142/192 = **73.96%** | 71/192 = 36.98% |
| D | 82/96 = **85.42%** | 41/96 = 42.71% |

非显眼 cue 的已知 bit 正确率分别为 R 97.02%、D 99.17%。因此外观变化确实伴随已有 reader 解码下降。但这个检查经过了冻结特征、投影、聚合和动态预测头，**不是编码器的直接线性探针**。仅凭它不能判断信息在哪一层丢失；下文新完成的探针进一步检查了聚合前的局部标签。

**Oracle 的 159 次语义冲突，不能全部解释成“缺信息时对冲更好”。**

S 的期望 MSE oracle 在 **159/1152** 个 parent 中删除了必要证据。它先对每种删除平均独立的 32 个评价动作计划，再选一次 argmin。相比之下，下面是保存的实际 episode 计划上的辅助诊断，二者不能偷换：

- 159 个中，完整 pair 预测错未来类别的为 **45 个**，另外 **114 个仍然分类正确**。
- 被 oracle 选中的缺信息预测，有 **67 个**比完整预测更接近两个未来原型的均值；另外 **92 个没有更接近**。
- 实际计划下，所选缺信息预测的 MSE 更低有 **141 个**，不是全部 159 个；这也体现了实际单计划与 32 计划平均的区别。

最近原型类别、特征 MSE、到原型均值的距离衡量的是不同性质。“分类正确”不等于 MSE 最小；靠近均值也不能直接证明模型采用了不确定性对冲机制。原型距离差不是经过校准的置信度。因此目前可以确认语义保留和这个 reader 的损失最优删除不完全一致，不能把全部冲突归因于同一个机制。

**单个 softmax 不等于在表达能力上不可能解协同任务。**

当前模型在权重之外还有加权 memory、velocity、时间与动作交互及非线性输出头。对独立逐项淘汰打分器证明的上界，不适用于读取整个聚合集合的非线性 reader。

一个直接反例：把四种局部 `(tag, payload)` 编成四维 one-hot，对三个候选取均值，就能恢复各类型的数量；非线性解码器可找到出现两次的 tag，再计算对应 payload 的 XOR。审计脚本完整枚举的 **48/48** 种组合都可恢复。这个反例只否定普遍的“不可能”断言，不证明现有 I-JEPA 特征、rank128 投影或训练出的预测头已经学会这套计算。

12 个真实标签探针在所有已报告显眼／非显眼分组均无错误，两类 recall 均为 1，选中的 λ 均为 100。12 个当前空白帧控制均为 50%。这强烈削弱了“这些局部 bit/tag 已经被 I-JEPA 或 rank128 投影丢掉”的解释，但不证明 reader 能找出匹配 pair、计算 XOR，或按正确时间和动作使用这些信息。探针按已知任务／方向分 head，也不是一个通用场景解析器。

**打乱标签控制并非全部 chance，不能省略。** 最突出的 projected R_b 总体为 75%，显眼 cue 子组为 91.67%。固定 TRAIN permutation 虽保留各层的标签计数，仍留下小样本局部类别相关，例如 R_b 显眼组与真实标签同号 52/96；离散词汇上的线性阈值可能放大这种相关，但这只是候选解释。打乱臂也按预注册使用真实 VAL 选 λ，其 family bootstrap 是条件于这一次 permutation／拟合的区间，不是 permutation-null 检验。保留原始结果，不重新随机到得到 50%。

36 个模型哈希、36 组 normal equations 和 264 组保存预测指标已经独立复算；TRAIN／VAL／DEV family 无交叉，最大相对 normal-equation 残差约 `1.15e-10`。完整记录在 `local-probes/manifest.json`、`local-probes-development/metrics.json` 和 `probe_analysis.json`，均位于 `build/reader-aggregation-20261025/`。零观察错误产生的 bootstrap [1,1] 不等于总体永远不会出错。

**已完成：同一个旧 checkpoint 改成 uniform，有利与不利结果同时出现。**

[干预脚本](../experiments/phase2/run_archived_reader_intervention.py) 在已发布的原 checkpoint 上，将所有有效历史项权重强制设为 `1/n`，并重算 memory、mean age、velocity、transport 及其动作交互；所有参数不变，没有训练。两次 CPU 评价各有 21312 条资格检查，checkpoint SHA 相同，各次内部的系数重构最大误差均为 0。原 forward 复现了旧 A100 的全部离散分类与门槛，但不是位级重放：主 MSE 字段最大差约 `5.47e-7`，预测系数最大差约 `6.87e-5`。下表每格为**原模型 → uniform**；正确率来自实际 episode 计划的未来特征原型识别。

| 任务 | K2 native 正确率 | K2 固定时间正确率 | K3 正确率 | K2 固定时间 MSE | K3 MSE |
|---|---:|---:|---:|---:|---:|
| R | 74.83% → **97.40%** | 76.39% → **97.40%** | 73.26% → **94.10%** | 0.05936 → **0.08522** | 0.06139 → **0.09124** |
| D | 84.38% → **98.26%** | 86.11% → **98.26%** | 84.38% → **68.75%** | 0.06525 → **0.08959** | 0.06476 → **0.15298** |
| S | 93.75% → 93.75% | 93.75% → 93.75% | 72.48% → **65.10%** | 0.08571 → 0.08552 | 0.10928 → **0.17168** |

R/D 的 K2 分类明显改善，却伴随 feature MSE 上升；D/S 的 K3 变差。因此不能概括为“均匀权重修好了 reader”。按原门槛，uniform 的 D K2 通过，S K2 仍通过，R K2 仍失败：其 `salient_unique` 完整 pair 固定时间 MSE 约 0.10863，反而高于缺证据的 0.10213。K3 则只有 R 通过。

S 的 K3 分层进一步说明这一点：正确 pair 为 tag=0 时，正确率 **50.35% → 65.28%**；为 tag=1 时，**94.62% → 64.93%**。抹平 tag 不对称同时修复与破坏了不同样本，没有恢复总体的关系读取。

这个干预证明**改变已有权重及其下游统计，会改变此 checkpoint 的行为**；它没有重新学习输出头来适应新的聚合分布。uniform 变差不能证明单 softmax 最优，局部改善也不能证明所有失败都来自 softmax。距离到真实特征与原型分类的分歧，以及固定读出面对输入分布变化的适应性，仍需分别解释。逐条结果和配对汇总保存在 `build/reader-aggregation-20261025/archived-intervention/`，独立复核为同层目录的 `archived_intervention_analysis.json`。

**S 的原有 medoid 保留失败仍然成立。** 旧模型的 S K2 资格本来就通过；medoid 丢必要证据 1103/1152，且实际计划下完整 pair 读对的 1080 条里仍有 1039 条被 medoid 删错。这里“读对”是实际计划诊断，不是宣称 32 个评价计划全部读对。新的探针和 K3 干预没有撤销这个结果，也不支持“所有保留失败其实都是 reader 问题”。保留失败和完整参照读取失败是可以同时存在的两个问题。

**正在 A100 执行的五臂实验，才会检验重新训练能否改善读出。**

五个臂是原模型、attention＋uniform 双通道、四头读取、条目 self-attention 后聚合、仅加宽原输出 MLP 的容量控制。参数量分别为 215297、313857、511364、347905、510927；容量控制与最大变体相差约 0.0855%，但未控制全部计算量和优化难度。训练日程、纯 MSE、配对初始化 seed17 相同，各自只按 VAL 选择 checkpoint。已经完成的旧 checkpoint 干预，不是这些新 reader 的结果。

新诊断 seed 20261120 只有在五个 checkpoint 与探针全部锁定后才能生成并查看；原 CONF 20261104 仍关闭。即使替代架构成功，这一轮也只是单个配对 seed 的读取诊断，没有证明新记忆方法、学生收益或独立最终确认。

与 PM 的联系仅限于 **readout adequacy**：让世界模型的输出指导记忆决定之前，要先验证该输出能使用相关证据。本轮没有运行 PM 的 S0–S2、CHANGE 或 BF-Delta，也没有新增 PM 结果。
