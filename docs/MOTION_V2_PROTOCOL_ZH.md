# Motion v2：让 Motion 真正考验"该留哪几帧"（草案，2026-10-30）

状态：设计草案 + CPU 上的无模型可行性检查。没有训练、编码或 GPU 作业；不改变 Phase 1 的登记结论。

## 1. 为什么 Phase 1 的 Motion 删除检查注定过不了

Phase 1 Motion 中，小球从 t=0 起就可见并匀速运动，直到 `end`；之后挡板一直盖到查询时刻。因此"可见"是时间上的一个前缀：越早的帧越可能有用，越新的帧越可能是挡板。

推论：在任意三帧候选池里，**删掉最新的那一帧（reject newest）永远不会丢掉比别的选择更多的可见帧**。用公开代码重建 seed 9137 的全部 Motion 测试池（每个 split 1,536 个，`scripts/motion_headroom.py`）：

| split | reject-newest 达到信息最优的池比例 | 最优选择下能恢复速度（≥2 可见帧）的池比例 |
|---|---:|---:|
| test_id | 100% | 60.9% |
| test_long_gap | 100% | 18.4% |
| test_distractor_shift | 100% | 62.6% |

失败的 8 项检查恰好都是 "oracle 删除 vs reject newest"。既然 reject newest 在每个池里都已信息最优，oracle 在位置上不可能有可靠增益；约 10% 的特征误差改善只能来自挑选哪一张"无关帧"（挡板帧）更像未来特征，而这与位置无关。长间隔下 81.6% 的池根本不含两张可见帧，任何删除都救不回速度。

在线 B=2 流式设定下同样成立：Phase 1 Motion 中"始终保留最早两帧"（keep first）成功率 100%（`scripts/motion_v2_headroom.py`）。这违背了 proposal 的数据原则："Cue timing, delays, and distractors will vary to prevent reliance on fixed storage schedules."

结论：长间隔 Motion 的失败首先是**任务设计没有给保留策略留空间**，不能据此判断删除代价监督在运动证据上无效。这一点本身是可报告的负结果解释，但需要组内复核（见第 5 节）。

## 2. Motion v2 设计

保持 Phase 1 的画面、动作接口、R=4、B=2、h=3/6、配对设计；只改时间结构：

1. **隐藏的开头**：t < t_on（0–6）为挡板，小球不可见，"保留最早帧"失效。
2. **过期的旧运动**：可见后先以速度 v0 运动 L0（4–10）步；两个配对样本的 v0 完全相同，因此这段帧对区分两者没有用（诱饵）。
3. **速度改变**：在 t_c 小球速度变为 v1（|v1| 0.008–0.012），配对样本 v1 方向相反，`end` 时刻位置严格相同；之后再可见 L1（3–7）步。
4. **随机短暂遮挡**：可见段内每帧以 25% 概率被挡（保证 t_c 之后至少 2 张可见、`end` 可见），让"按时间表保留"失效。
5. **长遮挡**：`end` 之后挡到查询时刻；ordinary 间隔 5–10，long gap 20–32；最近 4 帧全是挡板。
6. **干扰物**：场地外的干扰物逐帧随机移动（Phase 1 是静止的），给 diversity / surprise 制造无关变化。

充分条件（评估用，不给模型）：保留的两帧都可见且都在 t_c 之后——这样才能读出 v1 的方向和大小。只保留一张时无法区分配对样本。这是 proposal 所说的"联合必需"。

## 3. 无模型可行性检查（已完成，CPU）

在线 B=2，1,000 个 episode/条件，成功 = 查询时保留的两帧满足充分条件。diversity / surprise 用像素代替特征，只是粗略代理。

| 策略 | v1 ordinary | v1 long gap | v2 ordinary | v2 long gap |
|---|---:|---:|---:|---:|
| 事后最优（上限） | 100% | 100% | 100% | 100% |
| FIFO | 0% | 0% | 0% | 0% |
| keep first（reject newest） | **100%** | **100%** | 0% | 0% |
| reservoir | 32.8% | 8.8% | 3.2% | 1.0% |
| temporal buckets | 0% | 0% | 0% | 0% |
| 像素 diversity | 0% | 0% | 0% | 0% |
| 像素 surprise | 0% | 0% | 0.9% | 1.6% |
| 保留最新两张可见帧（结构参照，使用可见性） | 100% | 100% | 100% | 100% |

解读：v1 被一个平凡规则解决；v2 下 proposal 列出的通用 baseline 全部接近 0，而上限是 100%，留出了真实的保留空间。"保留最新两张可见帧"是知道任务结构的手写规则，作为类似"人工挑帧"的参照，不是需要击败的 baseline。删除代价学生的问题变成：它能否在不被告知结构的情况下学到这条规则，以及在特征空间而非像素上是否仍然成立。

## 4. 执行顺序与停止条件（需 GPU，未执行）

1. **生成与审计**：实现 v2 生成器（在 `envs.py` 基础上新增 `motion_v2`，不改 Phase 1 代码）；检查配对样本在 `end` 位置、v0、最近 4 帧上完全相同，只在 t_c 之后的帧不同。
2. **预测器能不能用对的帧（先过这一关）**：冻结 I-JEPA 编码，训练 v2 预测器（memory dropout，与 Phase 1 相同预算），比较 recent-only、特权 K=2（两张 t_c 后可见帧）、错误 K=2（两张 v0 段帧）。**停止条件**：特权 K=2 在解码位置误差上对 recent-only 的配对 95% 下界不大于 0，就先修预测器或读出，不训练保留策略。
3. **删除代价标签与学生**：按 proposal 在 K+1 父集上做等容量删除，标签用解码位置损失与特征损失两种版本分别训练；集合条件学生（DeepSets，同 10/26 设置）与独立学生、同架构 future-attention 学生、打乱标签学生对照。
4. **在线对比**：与 Gate 10/29 相同的在线 B=2 框架，baseline 用 FIFO、reservoir、temporal buckets、diversity、surprise、attention，外加 keep first 与结构参照。
5. **锁定确认**：上述全部锁定后，新 seed 生成确认集，只开一次。

预注册主张草案：在 v2 long gap 上，集合条件删除代价学生的"保留充分对"比例与位置误差同时优于全部通用 baseline 和同架构 future-attention 学生（配对 95% 下界 > 0）。
