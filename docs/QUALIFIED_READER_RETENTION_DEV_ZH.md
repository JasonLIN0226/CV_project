# 合格 reader 上的终局保留比较（DEV，2026-10-25）

**一句话：** 在两个通过全部 K2/K3 门槛的 reader 上，**以删除代价为标签的集合条件学生，在协同任务 S 上几乎不再删掉必要证据（4.8% / 0.6%），明显优于完整集合敏感度、attention、同架构的 future-attention 学生和独立学生，甚至优于逐 parent 的 MSE oracle。** 但同一类学生在冗余任务 R 上不泛化（约 35–39% 丢失），诱饵任务 D 可以被单条目外观捷径解决。这是开发集结果，CONF 仍未打开。

## 1. 做了什么

- **不需要 GPU。** 本地 `build/terminal-download-20261025/extracted/run/data/features.npy` 与 HPC 记录哈希一致（`9090806a…`）。在本机按 TRAIN basis 投影为 128 维后，全部计算在 CPU 上完成。
- **先复现再计算。** 用投影特征重跑 DEV 上 multihead / item_attention / original 的 native 与 full 预测，与 A100 存档系数最大差 3.0e-4，pooling 权重最大差 8.7e-6；学生输入与终局运行导出的 DEV `inputs.npz` 最大差 2.3e-5（数值量级 12），外观特征完全相同。再生成的 2208 张证据帧 RGB 与存档哈希 0 不一致。
- **先锁定再看结果。** 协议 `PROTOCOL_QUALIFIED_READER_RETENTION_20261025.md`（SHA256 `f467f363…`，UTC 01:32:11）写在生成任何标签、训练任何学生之前。此前只看过"实际计划近似版"的无训练规则结果，单独锁定在 `qualified_reader_rules_lock.md`。
- **方法：** FIFO、family 固定随机、diversity、reader attention（按头平均）、medoid、完整集合敏感度（均用 16 个 TRAIN 参考动作）、32 计划期望损失 oracle；学生用 `fit_terminal_students.py` 原样训练（独立 / DeepSets × 删除代价 / future-attention / 打乱，3 seeds，外观对照），另加预注册的"蒸馏敏感度"学生。
- **规模：** TRAIN 48、VAL 24、DEV 24 个 family；每个 reader 约 88.5 万次 reader 预测、78 个学生 checkpoint，全部 CPU（2 核）约 1.5 小时。

## 3. 能说什么

1. **S：删除代价监督加集合条件打分，第一次在开发集上胜过强对照。** 同一架构换成 future-attention 标签就失败（64.7% / 55.8%），换成独立架构也失败（62–64%，S 的设计决定任何逐条目打分至少丢 50%）。两个 reader 都重复了这个结果。注意 seed 方差：multihead 的三个 seed 分别丢 0、131、35 / 1152。
2. **学生超过了 oracle，原因是"平均"。** oracle 对每个 parent 取 MSE 最小的删除，会跟着 reader 的个别误差走；学生在许多 parent 上拟合平均标签，学到的是"删掉 tag 落单的那条"这种稳定规则。蒸馏敏感度学生同理，从老师的 32% 降到 9%（multihead）。
3. **oracle 在 S 上删必要证据，不是 MSE 混入了无关维度。** 只沿两个未来的差异方向计分，丢失率几乎不变（multihead 273→276，item_attention 147→130）。真正的原因是 reader 对协同的完整预测常常只比中点略偏一点，一个偶然偏对方向的对冲预测就能得分更低。关系型 reader（item_attention）承诺更强，把这个比例减半。
4. **完整集合敏感度：R/D 可用，S 不可靠。** item_attention 下 R 1.7%、D 0%；S 仍丢 32–39%，原因与第 3 点相同。
5. **medoid 在 D 上失败的机制已定位。** 由推导条件 `2⟨e_A,e_B⟩ < min(|e_A|², |e_B|²)` 判断的违反次数与 medoid 失败次数完全相等（129/129、117/117、120/120、111/111）；多数违反来自两个"缺一条证据"的预测误差同向（余弦 > 0.3），二者都还含着诱饵。
6. **attention 保留在强 reader 下仍然不行。** multihead 的按头平均 attention 在三族都差；item_attention 的 attention 只在 D 上好（2.1%）。

## 4. 不能说什么

- **R 上学生不泛化。** 学生在 TRAIN 上几乎完美（2/576），VAL 127/288、DEV 约 35–39%。48 个 TRAIN family 不足以学会"两条线索指向同一轴"，学生记住了每个 family 的具体样子。medoid、敏感度和 oracle 都能解 R，所以这是学生的数据量问题，不是任务做不到。
- **D 不检验集合推理。** 只看外观的独立对照就达到 0/288：诱饵带一个可见角标，单条目外观即可识别。D 上的学生成功不能算作集合学习的证据。
- **单个 reader 训练 seed、开发集已被多次查看**（用于 reader 资格和本轮分析），区间是 family 层面的描述性区间。
- 这是三候选、一次终局删除的合成任务，不是在线延迟信用、PushT 规划或自然视频。

## 5. 下一步

1. **一次性打开 CONF（seed 20261104，48 family）确认三条主张**：(a) S 上集合删除代价学生优于完整集合敏感度、attention 与 future-attention 学生；(b) 完整集合敏感度在 R/D 上接近 oracle；(c) medoid 在 D/S 上失败。需要 A100 编码新帧，脚本见结果目录 `conf/`，冻结的学生和规则不再改动。
2. **R 的泛化**：增加 TRAIN family，或让冗余的两条线索在外观上更多样，检验学生能否学到"同轴"规则而非记忆。
3. **重做 D**：去掉诱饵角标，否则 D 永远可以靠外观解决。
4. **reader 多 seed**：本轮所有依赖 reader 的结论都来自 seed17。

### 8.5 确认支持的范围与保留的限制

这次独立 CONF 支持的是：**在两个冻结的合格 reader 和这组终局协同任务上，集合删除代价学生稳定保留了必要证据；读取权重、完整集合敏感度与 medoid 并不自动等于有效保留。** 学生的语义丢失率可以低于 MSE oracle，因为 oracle 优化的是模型预测损失，不是必要证据标签；这不表示学生获得了比 oracle 更低的同一目标损失，也没有验证所有 DEV 机制解释。
