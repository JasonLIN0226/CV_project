# Baseline–oracle 诊断与两个 proposal 的连接

2026-10-22（纽约时间）。这次接着核查已发现的 CV 案例，并连接此前 PM 的 bad-case
结论；没有重新开启 PM 感知排查或泛泛寻找另一批坏例。所有结果仍是开发诊断，
没有把重复使用的场景当成独立确认，也没有宣布自己的 memory 方法已经成立。

**当前最重要的结论是：oracle 的事后优势，还不能直接当作“可学习的更好记忆”的
收益空间。** WR 的启动丢失已能通过共同输入的干预定位；保住 cue 后仍然预测错误，
以及同一有限记忆状态对应不同 oracle 动作，是另外两层问题。PM 的旧案例可以帮助
解释为什么必须分开这些层次，但不能拿来证明 CV 与 PM 有相同的失效原因。

## Proposal 要检验的主张没有改变

CV 的问题是：在固定预测器、近期上下文和历史容量下，能否用只依赖过去／当前的信息，
学会保留对未来预测更有价值的历史。Future-attention 是监督对照，删除损失是待检验的
任务价值监督；两者应使用相同输入、预测器、K 和多 horizon 目标。

本轮仍用一个共同动作最小化 `L = (L_h3 + L_h6) / 2`，没有让两个 horizon 分别选记忆。
局部 oracle 在同一个真实 K+1 parent 中枚举删除；历史选择 oracle 能访问已丢弃的全部
历史，只是特权诊断。两者都访问真实未来目标，不能直接部署。

WR-inspired 保留标准化 surprise、因果阈值及事件触发，另加明确容量规则；
PaFu-inspired 使用离线未来 attention 标签训练过去可用的 scorer。
它们是机制适配，不是两篇论文原视频系统的复现。已有 attention/diversity 仍是强对照。
机制边界与前一轮结果见[新场景报告](LITERATURE_BASELINE_FRESH_REPORT.md)。

## 1. WR：启动原因隔离成功，任务收益没有随保留率自动成立

对所有比较策略加入相同的四帧因果前缀：只复制第一张已经观察到的帧，移动后续时间戳，
保持原场景的相对时间、执行动作与未来目标。四帧由既定统计量的最少历史需求确定，
没有根据结果调参。固定子集的896次预测在时间平移前后完全相同，排除了这个操作本身
改变共同预测器数值的解释。

- 新192个 episode 中，原先 t=2/3 出现而全部丢失的62个早期 cue，现在 **62/62 保住**。
- 另外130个较晚 cue 的保留结果不变；FIFO/diversity 的全部224个新旧 episode 结果不变。
- 62个被救回的案例中，**41个 MSE 降低，21个反而升高**。
- WR 三条件均值依次由0.118781/0.102637/0.120981变为
  0.110006/0.097673/0.119013；只有 ID 的配对差95%区间完全低于0。

这证明当前 WR 适配的早期丢失来自启动过程，也证明“接纳并保存关键帧”不是任务改善的
充分条件。本轮仍没有检验“动态高惊讶干扰挤掉低惊讶线索”的最初假说。
前缀也有代价：WR 最大逻辑状态增加32字节，并多执行四步；不能称完全等总成本。
详见[WR 启动诊断](WR_STARTUP_DIAGNOSIS.md)。

## 2. 删掉 cue 为什么反而更好：需要同时检查读出和事后选择

上一轮在192个 episode 中发现46个全历史 oracle 严格偏好不含 cue 的 K2 子集。
本轮把预测误差沿“同一场景两个未来分支的差异方向”及其正交方向分解，并增加原始
feature 尺度和仅用旧 TRAIN 拟合的位置 probe，避免只看一个标准化 feature MSE。

在这46个已经选择出的坏例里，约83%的平均误差差距位于两个未来分支的差异方向；
删除 cue 后，41/46的该方向误差改善，45/46的原始 feature 误差改善，43/46的位置
probe 误差改善。位置 probe 在新外观上并不完美，所以这些不是物理任务成功率。
但结果**不支持把现象主要解释为“标准化 feature MSE 偏好错误物理结果”**：在多数
这些例子里，当前预测器读取保 cue 子集时的输出确实更偏向错误的未来分支。

将速度项置零没有消除这个现象；均匀 attention 可以缓解部分已选案例，但不能作为
全数据通用修复。这里改变 reader 的干预只是定位组件，不能拿改变后的 reader 与原
reader 的分数比较来宣称保留策略胜出。

输入支持域检查还排除了一个容易出现的误判。旧32条 TRAIN 的618帧只有48个唯一
feature，投影后的支持秩为47，有81个几乎未获支持的维度。原先仅用旧 TRAIN 拟合的
cue 线性 probe 在新场景约45–50%，但固定地屏蔽训练未支持系数、保持其余权重后，
cue probe 的 ID/long-gap/shift 准确率变为 **100%/100%/96.875%**；cue−current
版本为100%/98.4375%/100%。因此可用 feature 中确有可读的线索，不能把原 probe
失败解释为 encoder 丢失了 cue 信息。

然而，对冻结预测器输入施加对应支持域控制，attention baseline 的平均 MSE 只降低
0.000240，配对95%区间[−0.000465, −0.000042]；下面27个局部删 cue 案例 **一个也
没有被消除**，全历史46个只减少为45个。因此输入数值外推影响探针，却不足以解释
冻结预测器的这些局部反例；详见[输入支持域诊断](GATE_INPUT_SUPPORT_DIAGNOSIS.md)。

更严格地回到192个真实 attention K+1 parent：其中120个已有两个等价 cue 副本，
一次删除无法让 cue 完全消失；只有72个允许直接比较“保 cue／不保 cue”。在这72个
parent 内，27个严格偏好删除全部 cue。这27个的平均保 cue 代价为0.060659，
其中0.052706来自未来分支差异方向，0.007954来自正交误差；26/27的原始 feature
误差、25/27的位置 probe 误差也随删除改善。这排除了用不同候选档案解释全部现象。
但交换 cue 与非 cue 项时，时间戳和已执行动作摘要也改变：**它证明保 cue 子集在
冻结 reader 上预测更差，尚未把 cue 内容、时间和动作因素完全分离。** 不能据此
唯一归因为 cue 的视觉内容有害。

同时，历史选择 oracle 的优势确实混入了**事后挑时间索引**：全部192个 episode 的
非 cue 历史 feature 都相同；给 sibling 同一个不含 cue 的时间子集，预测逐位相同。
但事后 oracle 在全部96对 sibling 中选择了不同的最优时间子集。它用未来结果
选择不同的时间组合，借此改变共享预测器的输出。因此，事后不含 cue 的分支准确率
不能充当一个“过去可用、无需 cue 的好预测器”的证据。

两点同时成立：真实同 parent 中有保 cue 子集读出更差的案例；全历史 oracle 还额外
利用未来选择时间。不能把后者全部归于预测器，也不能用后者否认前者。
数值分解和完整 parent 记录见
[reader／metric 归档](../results/literature_diagnosis/metric-reader-20261022/)。

## 3. Oracle 决策的可学性：输入外推足以翻转 probe 排序

采用预先固定的线性 ridge probe：只在旧 TRAIN 的16对场景、1,282个 parent 上拟合，
固定正则系数，不用新数据选参。任务损失、未来 attention 和打乱任务标签三个 arm
具有相同的903维输入和参数数目；运行时只看允许的过去／当前特征。
这是一项可学性诊断，不是 proposal 新方法的最终训练。

第一次得到删除代价 probe 更差的结果，但输入检查发现严重的训练外数值放大。
因此又冻结了一个共同的数值控制：不重训，把旧 TRAIN 的 parent-centered 特征 RMS
触及1e−6下限的710列系数置零，三个 arm 使用相同 mask，保持903个系数的分配与
完整输入接口。该 mask 的实验修订在读取控制结果前保存；它是发现不稳定性后的
探索性干预，不能称预先独立确认。

| 新192个 episode 的在线回放 | 原 probe MSE | 同一 TRAIN 支持 mask 后 MSE |
|---|---:|---:|
| 删除代价 ridge | 0.120286 | 0.112316 |
| 相同模型的 attention ridge | 0.112479 | 0.120131 |
| 打乱删除代价标签的 ridge | 0.122339 | 0.110272 |

原来删除代价比 attention probe 差0.007807；控制后变为好0.007814，配对95%区间
[−0.015363, −0.000233]。这说明**数值外推就足以翻转监督目标的排序**，不能用原
负结果断言未来删除价值不可学。

但反向结论同样不成立：控制后的任务标签仍未胜过打乱标签，其差为+0.002045，
区间[−0.001354, 0.005576]；相对现有 reader-attention、diversity、PaFu 的差区间
也都跨0。共同 parent 上的结果方向相同。因此本轮没有建立任务标签的稳健优势，
也没有证明不可学；两个版本均保留，而不是只选择有利的一版。

精确输入检查还发现了更直接的限制：在1,121个共同 parent 中，231组跨 sibling 的
有限状态完全相同，却对应不同未来；其中217组的严格最优动作不同。这些状态已经
丢失区分未来分支的证据。相同状态上的同一个 scorer 不能为两者输出不同动作。
但完整已观察历史没有这种碰撞，因此不能宣布“任何过去策略都不可能”：更早保住
区分证据，可能避免到达这些混淆状态。这217组冲突的未来动作也完全相同，排除了
把冲突简单归因于不同动作计划的解释。

这也解释了为什么不能仅比较各在线策略自己的局部 regret：坏策略到达的信息不足
parent 可能有很小的可选差距，却依然预测更差。要同时报告共同 parent 的动作质量、
持续回放的任务损失与证据生存率。
详见[可学性诊断](ORACLE_LEARNABILITY_DIAGNOSIS.md)及
[冻结结果](../results/literature_diagnosis/learnability-20261022/summary.json)。

## 4. 与自己的 PM 已有 bad case 怎样结合

PM 本轮只回看已保存的864个 residual-bank parent，没有新建 PM 坏例搜索，也没有
回到像素感知诊断。对同一 K+1 输入的原选择与局部 oracle 使用相同 K、近期缓冲、
masked-mean reader 和六步目标；重新计算25,056个删除损失，最大差1.78×10⁻¹⁵。

旧 R25/R50 身份及 O/W/key 检查通过后，可以分解注入前 signal、已实现 noise 和
cross term。这里 signal 是标准化的 slow-model residual，**不是物理无噪状态真值**；
原始完整 L0、动作和 pose 仍然缺失。

| 已有 PM 结果 | 与 CV 能共同检验的问题 | 不能合并的结论 |
|---|---|---|
| 原 K16/PaFu/CHANGE 案例：teacher 给旧 key 全部 attention，但删掉它将 MPE 从3.118468降至0.810922 | “未来会读取”是否等于“读取比不用更有帮助”；需要条件增量贡献对照 | 该 oracle 仍比零残差输出0.590660差；不能称找到了有用的新状态记忆，或击败了原 PaFu |
| 129个有正 regret 的 parent 中，48个总误差降低但 signal 变差；96个删除后历史覆盖下降 | 事后损失标签可能包含噪声实现、读取器错误和放弃读取的收益 | 不能把所有 oracle 收益都叫作保留更多任务信息；这也不是 CV 的因果解释 |
| K64 PaFu 平均 regret 的82.6%来自已实现 noise 项；signal 均值区间跨0 | 单个未来实现的删除标签是否偏离可预测的期望贡献 | 最大 CHANGE 案例主要是 signal 失配，不能用一个例子解释整个均值 |
| 旧 A2 的 EXACT 物体坐标有局部 signal 代价，同时降噪、grid 获益，CHANGE 坐标改善 | 更新必须权衡保护、改写和降噪，平均损失可能掩盖局部分量 | 原先仅0.0125%的合并 MPE 账面修复空间仍然太小，不重新包装成论文主线 |

原 PaFu 大坏例中的删除把 scored-coordinate 历史覆盖从93.90%降至34.15%，对失去
匹配的 key 输出零残差。它支持“读入有害旧值，退回不读反而更好”，并没有证明删除恢复了
正确的新状态；条目年龄450步只是描述，未被单独隔离为原因。旧 A2 是降噪和局部
signal 损失的交换，而这个 raw bank 还可能引入旧噪声，二者机制方向不同。

**能共用的是问题和证据链，不能共用模型权重、总分或失效原因。** CV 固定历史帧
预测器；PM A2 是矩阵状态更新；PM bank 是退化 residual reader。即使历史项数或
字节预算相同，表示和读取方式也不同，不能把跨表示差异全部归因于淘汰。

PM 完整结果保留在 [predictive-memory-lab PR #6](https://github.com/XintongYang1010/predictive-memory-lab/pull/6)
的 `experiments/bank_reference/results/br-0.2-connect-20261022/ASSESSMENT_ZH.md`，
含旧 A2 结论原样副本、全部 parent 分解、已有案例和来源哈希。
PM 的864个有限候选状态没有精确重复，当前归档不能回答同状态异未来的可学性；
不能把 CV 的217组冲突直接转移成 PM 结论。

## 按 proposal 下一步做什么

本轮证据要求先把“未来任务价值”定义与共同预测器的能力核查清楚，再决定是否值得
扩大自己的删除价值 scorer。这里没有新增 proposal 原文没有的性能阈值，也不把开发
失败改成通过；按以下顺序推进可减少归因混淆：

1. **固定证据后核查预测。** 在真实同 parent、相同 filler 的条件下，报告 cue 对
   未来分支及物理任务 probe 的贡献；把时间索引的事后选择优势单列。若更换共同预测器，
   所有 baseline 都在同一新 reader 上重跑，旧负结果继续保留。
2. **将成功与失败配对。** 静态回访保留“惊讶确实重要”的正对照；状态更新沿 PM
   proposal 比较真实变化、未变化、闪烁/噪声，保护未变化对象。需要同输入、同内存
   状态预算、同任务损失，不能靠换 reader 获得保留器的胜利。
3. **区分可恢复缺口与事后优势。** 只把过去可判断、对任务有贡献的部分作为新 scorer
   的潜在目标；共同 parent 排序与完整在线回放都要优于强 attention/diversity。
   当前 ridge 对支持域控制敏感的结果和有限状态冲突均应保留，不能靠选择坏例绕开。
4. **控制成本和结论范围。** 统计历史项、Gaussian 统计量、索引、controller 的实际
   持久字节，训练与推理时间另列；继续使用开发数据时明确这一身份。
   PushT 的模型驱动 baseline planning、Motion 的历史收益和最终确认都没有被这轮
   Gate 诊断代替。

与 Saining 可以讨论的具体主张是：**surprise、attention、单次未来损失是三种不同
信号；研究的关键在于，有没有稳定且可因果判断的证据贡献，被前两种代理遗漏。**
目前找到了代理之间的分歧及当前 pipeline 的限制，尚未证明自己的任务价值监督能
解决它。PM 的既有案例加强了这个检验要求，而非为尚未成立的方法补上成功证据。
